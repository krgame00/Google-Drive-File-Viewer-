# แผนปรับการดูวิดีโอและภาพบนมือถือ

> **For agentic workers:** REQUIRED SUB-SKILL: Use subagent-driven-development or executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** ทำให้ผู้ใช้เข้าใจปัญหาการเล่นวิดีโอได้ทันที และดูภาพบนมือถือได้เต็มพื้นที่พร้อมซูมและซ่อนปุ่มควบคุม

**Architecture:** ปรับหน้าดูสื่อเดิมใน `index.html` และการรายงานข้อผิดพลาดจาก `drive-stream-sw.js` โดยรักษาระบบบัญชีและการสตรีมเดิม แยกสถานะวิดีโอออกจากสถานะซูมภาพ และยกเลิก callback ของไฟล์เก่าเมื่อปิดหรือเปลี่ยนไฟล์ ทดสอบพฤติกรรมด้วย Node VM และตรวจการสัมผัสกับการเล่นจริงบนมือถือแยกกัน

**Tech Stack:** HTML/CSS, JavaScript, HTMLMediaElement, Service Worker, Pointer Events, Node.js tests

## ขอบเขตและข้อกำหนดร่วม

- ต่อยอด commit `2352c25`: สตรีมด้วยบัญชีรอสูงสุด 60 วินาที และไม่สลับเข้าพรีวิว Google อัตโนมัติเมื่อผิดพลาด
- UI ภาษาไทย ใช้ปุ่มและรูปแบบสีเดิม ปุ่มสัมผัสอย่างน้อย 44 × 44 CSS pixels
- ไม่เก็บ OAuth token ใน localStorage, URL, cache หรือ log และไม่ส่ง token ไป Cloudflare
- การสตรีมยังอยู่ภายใต้สิทธิ์ดาวน์โหลด โควตา และรูปแบบสื่อที่เบราว์เซอร์รองรับ
- ไม่แสดงเปอร์เซ็นต์ดาวน์โหลดที่คำนวณไม่ได้จริง
- เก็บภาพครบและรักษาสัดส่วนเป็นค่าเริ่มต้น; พื้นที่ว่างที่เกิดจากสัดส่วนภาพไม่ถือว่าเป็นบั๊ก
- แผนนี้ยังไม่เริ่มแก้โปรแกรมหรือ deploy; commit/push เมื่อผู้ใช้สั่ง
- หลักฐานจากชุดทดสอบจำลองไม่ถือว่าเป็นผลทดสอบ Brave Android จริง

## ช่วง 1: สถานะเครื่องเล่นและปุ่มแก้ปัญหา — สำคัญที่สุด

**ไฟล์:** `index.html`, `drive-stream-sw.js`, `tests/authenticated-stream.cjs`, `tests/media-lifecycle.cjs`, `docs/authenticated-video.md`

**สถานะที่ใช้:** `connecting`, `loading`, `playing`, `buffering`, `error`, `preview`, `closed`

**Interface:** `setVideoStatus(state, message)` อัปเดตข้อความและปุ่ม; การแจ้งจาก worker ต้องผูกกับ file ID และรหัสความพยายามเล่น เพื่อไม่ให้ข้อผิดพลาดเก่าทับการลองใหม่ของไฟล์เดียวกัน

- [x] เพิ่มกรณีทดสอบ: เริ่มเชื่อมต่อ → โหลด → เล่น; ข้อผิดพลาดของ session เก่าห้ามทับไฟล์ใหม่หรือการลองเล่นใหม่
- [x] รันทดสอบก่อนแก้และตรวจว่ากรณีใหม่ล้มเหลวตามที่คาด
- [x] ใช้ `loadedmetadata`, `playing`, `waiting`, `error` และ timer ที่ยกเลิกได้เพื่อแสดงสถานะจริง; โหลดช้าให้ขึ้นข้อความหลัง 15 วินาที แต่คงเพดานเริ่มสตรีมด้วยบัญชีที่ 60 วินาที
- [x] แสดงการแก้ที่ตรงสาเหตุ: session หมดอายุ → เชื่อมต่อใหม่; permission → ตรวจบัญชี/เปิด Drive; quota → ลองภายหลัง; timeout/network → ลองใหม่; รูปแบบไม่รองรับ → เปิด Drive หรือดาวน์โหลด
- [x] แยก HTTP error จาก Google กับ media error ของเบราว์เซอร์; media error เพียงอย่างเดียวห้ามสรุปว่าเป็น quota หรือ codec แน่นอน
- [x] เมื่อเข้า Google preview ให้บอกว่าการลงชื่อเข้าใช้ในพรีวิวแยกจากบัญชีที่เชื่อมต่อในเว็บเรา
- [x] ยกเลิก timer/listener และ unload สื่อเมื่อปิดหรือเปลี่ยนไฟล์; เพิ่มคำอธิบายให้ปุ่มใน UI และสถานะ `aria-live="polite"`
- [x] แก้เอกสาร `docs/authenticated-video.md` ที่ยังระบุว่า fallback อัตโนมัติ ให้ตรงกับพฤติกรรมใหม่
- [x] รัน `node --test tests/authenticated-stream.cjs tests/media-lifecycle.cjs` ต้องผ่านทั้งหมด

**ตรวจรับ:** ไม่ค้างข้อความกำลังโหลดหลังเล่นสำเร็จ ไม่ให้ข้อผิดพลาดเก่าทับไฟล์ปัจจุบัน และทุกข้อความผิดพลาดมีการแก้ที่ผู้ใช้ทำได้

## ช่วง 2: ทดสอบเครื่องเล่นบนมือถือจริง — ก่อนเพิ่มฟีเจอร์ภาพ

**ไฟล์:** สร้าง `docs/mobile-media-acceptance-2026-09-30.md` สำหรับหลักฐาน; แก้ `index.html` หรือ `drive-stream-sw.js` เฉพาะเมื่อพบและยืนยันปัญหา

- [ ] บันทึกชื่อ/เวอร์ชัน browser, Android/iOS, ขนาด viewport, วันที่, commit ที่ทดสอบ และสถานะการเชื่อมต่อบัญชี; ไม่บันทึก token หรือข้อมูลบัญชีส่วนตัว
- [ ] ใช้คลิปทดสอบที่ไม่อ่อนไหวและมีสิทธิ์เข้าถึง: MP4 ขนาดเล็ก, MP4 ขนาดใหญ่ และวิดีโอแนวตั้ง; สร้างข้อผิดพลาดจำลองสำหรับ quota/permission โดยไม่สร้างโหลดเพื่อให้ติดโควตาจริง
- [ ] ทดสอบ Brave Android เป็นเครื่องหลัก; Chrome Android เป็นเครื่องเปรียบเทียบ; Safari iPhone เมื่อมีอุปกรณ์จริง และระบุว่ายังไม่ได้ทดสอบหากไม่มี
- [ ] ตรวจเล่น/หยุด/เลื่อนเวลา/เล่นต่อจากจุดเดิม บนเครือข่ายปกติและช้า
- [ ] ตรวจหมุนจอ เข้า/ออกเต็มจอ เปิดแท็บ Drive แล้วกลับเว็บ ปิดแล้วเลื่อนหน้า และเปิดไฟล์ใหม่อย่างรวดเร็ว
- [ ] ตรวจขาดเครือข่ายระหว่างโหลด token หมดอายุ และ reconnect; ต้องไม่เกิดเครื่องเล่นซ้อนหรือ callback เก่ากลับมาเปิดสื่อ
- [ ] บันทึกผลแต่ละกรณีเป็น ผ่าน/ไม่ผ่าน/ยังไม่ได้ทดสอบ พร้อมอาการและขั้นตอนทำซ้ำ

**ตรวจรับ:** Brave Android จริงผ่านกรณีหลักทั้งหมด; browser ที่ยังไม่มีอุปกรณ์ไม่ถือว่าผ่านจากการจำลองหน้าจอ

## ช่วง 3: ซูมภาพด้วยสองนิ้วและลากภาพ

**ไฟล์:** `index.html`, สร้าง `tests/image-viewer.cjs`

**Interface:** สถานะภาพ `{scale, x, y}` โดย scale อยู่ระหว่าง 1–4; `resetImageView()` คืนค่า 1/0/0; `clampImagePan()` จำกัดการลากตามกรอบภาพที่แสดงจริงและ viewport

- [x] เพิ่มทดสอบการจำกัด scale, การลากไม่หลุดกรอบ, reset เมื่อเปลี่ยน/ปิดภาพ และ pinch ที่ห้ามเปลี่ยนไปภาพถัดไปโดยไม่ตั้งใจ
- [x] รัน `node --test tests/image-viewer.cjs` ก่อน implementation; กรณีใหม่ต้องล้มเหลว
- [x] ใช้ Pointer Events และ pointer capture กับพื้นที่ภาพ ติดตามระยะและจุดกึ่งกลางของสองนิ้วเพื่อซูม; จำกัด `touch-action` เฉพาะตัวดูภาพ ไม่เปลี่ยนการซูมของทั้งเว็บไซต์
- [x] ขณะ scale > 1 นิ้วเดียวลากภาพ; ขณะ scale = 1 นิ้วเดียวปัดเปลี่ยนภาพได้ตามพฤติกรรมเดิม; ยกเลิก gesture เมื่อ `pointercancel` หรือสูญเสีย capture
- [x] แตะสองครั้งสลับระหว่างขนาดพอดีจอกับ 2 เท่า; เพิ่มปุ่มคืนขนาดที่ใช้ได้ทั้งสัมผัสและคีย์บอร์ด
- [x] เมื่อเปลี่ยนภาพ ปิดภาพ หรือหมุนจอ ให้คืนขนาดพอดีจอและล้าง gesture/timer เก่า
- [ ] ใช้ภาพทดสอบทั่วไปแนวตั้ง แนวนอน และภาพสี่เหลี่ยม ตรวจ pinch/pan จริงบนมือถือและรันชุดทดสอบภาพ

**ตรวจรับ:** ซูม/ลากได้โดยไม่เปลี่ยนภาพเอง คืนขนาดได้ทันที ภาพใหม่เปิดด้วยขนาดพอดีจอ และหน้าเว็บเลื่อนได้หลังปิด

## ช่วง 4: แตะภาพเพื่อซ่อน/แสดงแถบควบคุม

**ไฟล์:** `index.html`, `tests/image-viewer.cjs`, `tests/media-lifecycle.cjs`

**Interface:** `setImageControlsVisible(visible)` ตั้งสถานะ controls; ใช้สถานะเดียวกันกับ `aria-hidden` และการรับ focus

- [x] เพิ่มทดสอบ: แตะเดี่ยวสลับปุ่ม; double tap ไม่สลับปุ่ม; pinch/pan/แตะปุ่มไม่ถูกตีความเป็นแตะภาพ; เปิดภาพใหม่ต้องเห็นปุ่ม
- [x] หน่วง single tap 280 ms เพื่อรอ double tap และยกเลิก timer เมื่อปิด/เปลี่ยนภาพ
- [x] ซ่อนเฉพาะปุ่มและตัวนับ; การแตะภาพครั้งต่อไปต้องเรียกกลับได้ ไม่มี timer ซ่อนเองระหว่างที่ผู้ใช้กำลังกดปุ่ม
- [x] Controls ที่ซ่อนต้องไม่รับ Tab; ถ้า controls มี keyboard focus ให้คงแสดงไว้; Escape ยังคงปิด และปุ่มลูกศรยังเปลี่ยนภาพได้
- [x] เคารพ `prefers-reduced-motion` และ safe-area; ตรวจพื้นที่สัมผัสบนจอแนวตั้ง/แนวนอน
- [x] รัน `node --test tests/image-viewer.cjs tests/media-lifecycle.cjs` ต้องผ่าน

**ตรวจรับ:** ดูภาพโดยไม่มีปุ่มบังได้ เรียกปุ่มกลับง่าย ไม่มีปุ่มล่องหนรับการกด และ gesture ซูมไม่ขัดกับการซ่อนปุ่ม
